Set up Media Hub

New installation? The tutorial opens automatically for the Jellyfin administrator. You can pause, resume or restart it here at any time without resetting saved settings.

No bot experience needed. Follow one step at a time, using the real settings forms inside the relevant steps. Back/Next never save or enable an integration: only the labelled Save buttons do that.

Test preview only: use a new test Discord application/server and leave automatic deletion off. Live provider/Activity acceptance is incomplete. Ordinary users link their own accounts from the main Media Hub page; the administrator completes this server-setup tutorial.

A Discord application holds your bot and optional Activity (the web interface inside Discord). A Discord server is also called a guild. A slash command starts by typing / in a server's message box. An intent selects events sent to the bot; it is not a server-role permission.

Welcome · your plugin setup

  1. Sign into Jellyfin Web as its administrator. Open Dashboard → Plugins → installed/My Plugins → Media Hub (Preview) → settings. An installed plugin ZIP and host restart are needed; source files alone do not install it.
  2. This tutorial will guide you through creating a Discord application, permissions, server IDs, connection settings, optional messaging/Activity and your first account link. Your preferences remains personal; this tutorial configures the plugin's server integration.
  3. The real configuration forms appear as you reach their steps. Save plugin settings saves the connection form; Save integrations saves optional integrations. A saved notice does not prove that an external service works.
  4. Ordinary users need compatible Jellyfin-12 Plugin Pages and File Transformation for the user-facing page/login resume. Open Jellyfin's main menu (usually three lines at top left) → Media Hub. If missing, ask the owner to install compatible companions; do not make a viewer an administrator to let them link.

Check: you are signed in as the Jellyfin administrator. The plugin runs inside Jellyfin and uses its existing authenticated settings page and listener; no extra admin port or runtime is needed. Tutorial progress stays in this browser for this user/server; credentials never go into tutorial storage.

Create the Discord app and keep its secrets private

  1. Open Discord Developer Portal, sign in, click New Application, enter a test name such as Media Hub Test, and click Create.
  2. In its left sidebar, General Information → copy Application ID. Then Bot → use the existing bot user, or Add Bot if offered → Token → Reset Token if needed. Complete Discord's security prompt and store the token in a password manager. Resetting it invalidates the old token.
  3. Leave Requires OAuth2 Code Grant and all privileged intents off for now. Leave Interactions Endpoint URL blank: this plugin connects outward to Discord's Gateway, not an incoming interaction webhook.
Bot token — secret
Bot → Token. Goes only in Discord bot token below. Not an Application ID or OAuth client secret.
Application ID / Client ID — not a password
General Information / OAuth2. Identifies this app; used for optional OAuth and Activity.
OAuth client secret — a different secret
OAuth2 → Client Secret. Used in the Activity step, not in the bot-token field.
Server ID / user ID / channel ID — different numbers
Copied from the Discord client in step 4. A name, invite link or Application ID is not your Server ID.

Check: you know which app the token belongs to. Never put secrets in chat, screenshots, support issues, URLs, Activity mappings or frontend files. If leaked, rotate the affected provider secret and update its native password field; do not delete plugin state.

Invite the bot and set limited permissions

  1. Developer Portal → your app → Installation → enable Guild Install. Choose Discord Provided Link and, under Guild Install defaults, select scopes bot and applications.commands. A user-only installation is not sufficient.
  2. For the bot, allow View Channels, Send Messages, Embed Links, Read Message History. Add Attach Files only for attachments and Send Messages in Threads only for threads. Start in a normal text channel.
  3. Save, copy Install Link, open it, choose Add to Server → your test server → Continue → Authorize. The installing person needs Manage Server; the bot does not. If your Portal uses OAuth2 → URL Generator, select the same scopes/permissions there instead.
  4. In Discord create #media-hub-test. Right-click it → Edit Channel → Permissions; check the bot's role and inherited category overrides allow the chosen permissions. Also let human testers view/send and Use Application Commands. Server Settings → Integrations → your app can restrict commands further.

Do not grant Administrator, Manage Server/Roles/Channels/Messages/Webhooks, mass mentions, or voice Connect/Speak to the bot. It is not a voice-streaming bot. Human Activity users later need Use Activities (Use Embedded Activities), plus normal voice-channel access if testing in voice.

Check: the bot appears in your test server; offline is normal until step 5. Do not fix a denied channel by granting Administrator or moving the role above everyone.

Copy the correct Discord IDs

  1. In the Discord client click the gear beside your username → User Settings → Advanced → Developer Mode → on. Close Settings.
  2. Right-click the test server's icon in the leftmost column → Copy Server ID. This goes in Allowed Discord server IDs below.
  3. Right-click your own avatar/user → Copy User ID. Use it for your account link and, only if wanted, Operator Discord IDs. Right-click the test channel → Copy Channel ID for optional inbox retention.

Check: label each number. Never substitute the application's ID, a server name or an invite link for a Server ID. A blank server allowlist does not mean allow everyone.

Save the connection settings, then connect the bot

  1. In Plugin settings below, leave automatic deletion off and keep the default 14-day activity window / 2-day deletion delay. Leave Discord integration off for the first save.
  2. Public Jellyfin URL is your existing user-facing HTTPS base, for example https://media.example/jellyfin. Replace the example. Include your host's real base path, not /web, a login page, query or token. The plugin does not create HTTPS hosting; ask the hosting administrator if it is missing. No VPN/DNS/network reassignment is needed.
  3. Paste the explicit test Server ID and the bot token. For movie/TV discovery/requests enter Seerr's reachable base URL (no /api/v1) and its administrator API key, normally Seerr → Settings → General. Jellyfin's process/container must reach it; localhost inside a container means that container.
  4. In Seerr, use its supported user-import/account workflow so each viewer maps to exactly their Jellyfin user. Manage request permissions/quotas in Seerr; a similar name does not prove identity. Existing Seerr requests and service routing stay in place.
  5. Use the form in this step and click Save plugin settings. Blank password fields after saving intentionally keep the saved secrets. Once ready, ensure this application token is used by only this plugin instance, tick Enable Discord integration, and Save plugin settings again.
  6. In #media-hub-test type /, choose your test app, then /hub-link. The plugin registers server commands on connection; you do not run a registration script.

Check: /hub-link replies privately with your Discord ID and a short-lived fallback code. That proves the command path, not Seerr access. Do not send requests, broadcasts or deletions to test basic connectivity.

Link your own account and try a safe read

  1. Request your own /hub-link or /link in the allowed server. In your own browser sign into your own Jellyfin account, open Media Hub, and paste the private fallback code and displayed Discord ID into Link Discord below. Click Link account. Codes expire after five minutes.
  2. If Link in Jellyfin is offered after OAuth setup, open it, choose Verify Discord in this browser, check both identities on return, then explicitly Confirm these accounts. Opening a link or its callback alone does not approve it. Never ask an administrator to approve your code while signed into their account.
  3. Try /dashboard and /library in Discord. Use Discover or Your requests to test the viewer's Seerr mapping. An empty test library is allowed. Prepare request is only a preview; Confirm request actually sends it, so skip confirmation for a read-only test.
  4. Your preferences controls personal notifications; Discord DMs need opt-in and Mute wins. Save preferences does not configure integrations. Opening media Details is an explicit interaction that may update last-played time, not completion/progress/favorites.

Check: a linked ordinary user sees only permitted media and cannot configure the server. Only approve codes/links you requested yourself. Watch-party invitations remain blocked without exact creator-player proof; do not bypass that safety gate. Activity is not the native player.

Optional operator inbox, intents and announcements

Slash commands/buttons and Activity sign-in do not require privileged intents. Leave them off unless you choose the matching messaging feature.

  • Full non-mention server-message content: Developer Portal → Bot → Privileged Gateway Intents → Message Content Intent on, and Media Hub → Message Content Intent on.
  • All-member announcement DMs: Portal → Server Members Intent on, and Media Hub → Members Intent on. Keep the announcement's all-member option off for your first test. Presence Intent stays off.
  • Both sides must match; larger/verified apps may require Discord approval. Channel permissions still apply. The inbox retains eligible incoming events, not a complete channel history.
  • Operator Discord IDs should start empty, or contain only your own user ID for a test. Operators can read the bot's shared private DM inbox. A Jellyfin admin/Discord moderator role alone does not grant this access; a live linked identity is still required. Leave Also allow verified Seerr administrators off unless intentionally wanted.
  • Choose retained channel IDs, explain retention to members, and start with a small recipient limit. Click Save integrations. Test just one intended channel/recipient; announcements require a preview and confirmation. A blocked DM can be the recipient's privacy choice.

Check: an unassigned ordinary user cannot open Operator messenger. Never grant Administrator to repair message-content or file-permission problems. An uncertain delivery/request may already have happened: check its receipt/upstream state, do not automatically resend.

Optional web Activity · OAuth, mapping and first launch

You can leave Activity off and use native pages/slash commands. Activity uses the bundled frontend/API on Jellyfin's existing listener; no separate backend or new port. The existing HTTPS hostname must be reachable by Discord's proxy with a trusted certificate and correct base-path routing. Do not expose Seerr/Arr, disable authentication/certificate/frame checks, or change working networks to make it load; ask the hosting administrator.

  1. In the same Developer Portal application → OAuth2, get Client ID/Application ID and Client Secret. Under Redirects add your exact linking callback: for base https://media.example/jellyfin use https://media.example/jellyfin/MediaHub/Link/OAuth/Callback. Replace the hostname/path; no extra trailing slash.
  2. Also add https://127.0.0.1, Discord Embedded App SDK's documented placeholder redirect, and save. Keep the real linking callback too. The placeholder is not your hosting address and needs no exposed loopback service.
  3. Activities → Settings → Enable Activities; enable the supported web/desktop platform you are testing. Activities → URL Mappings → prefix / → target media.example/jellyfin/MediaHub/Activity/ → save. With no Jellyfin base path use jellyfin.example/MediaHub/Activity/. No https:// in Target; map the directory, not /App, an HTML file, /web or a media service.
  4. In Music, books and messaging below, enter the matching application ID and OAuth client secret together, leave OAuth PKCE checked, tick Enable optional Discord Activity, and Save integrations. A missing bundle requires a corrected plugin ZIP from the maintainer, not a new frontend server.
  5. In Discord as the app owner/trusted team tester, enable Developer Mode, open the allowed test server, use its App Launcher (or Activities/rocket in voice), find the app by name and choose Launch. Enabling Activities normally creates Discord's managed Launch Entry Point; keep that behavior. The native plugin does not register /activity.
  6. Approve identify and guilds to verify your Discord identity/server membership. If shown Link Jellyfin, open it and finish the native same-browser verification and explicit account confirmation. Return to Activity and choose Check link. Then browse permitted media.

Human launchers need Use Activities / Use Application Commands. Unpublished Activity testing may be owner/developer-team only; bot installation does not publish it. Do not add ordinary viewers to the developer team to bypass distribution restrictions. DMs/group DMs are not supported Activity contexts here.

Check: launch and authenticate inside Discord through the real mapping. Opening /Activity/App in a normal browser only shows an SDK-dependent app, not proof of working sign-in. Reopen when verification expires. Activity cannot configure the server or impersonate a player; Open in Jellyfin uses the native client. Use this host's colors in Activity in personal preferences copies only four validated colors, not arbitrary CSS or the full theme.

Optional media services · leave deletion off

Movie/TV requests retain Seerr's permissions, quotas and routing. For storage inspection or eventual deletion, Approved Arr destinations needs independent approval of each service, Seerr's instance ID and exact URL. Instance is not the port, profile or list position. Leave [] until the administrator has verified those values; do not guess or share settings responses containing keys. The form currently has no instance-discovery picker.

Optional Lidarr/Readarr need their own URL/key pair and existing root-folder, quality-profile ID and metadata-profile ID. Leave both URL/key blank and requests off if unused. These values come from that service, not your Jellyfin media path. Do not create/delete host folders as setup.

Keep automatic deletion off in this preview. Original-requester ownership, current recent-viewer consent and a full delay are mandatory; administrators cannot bypass ownership. Arr performs file removal, not this plugin's filesystem. No setup step needs to delete media.

Review your setup and finish the tutorial

  • Offline or no commands: correct bot token, saved enable switch, Guild Install + bot + applications.commands, explicit Server ID, actual channel/Integrations command permissions, existing outbound connectivity. No incoming Interactions Endpoint or registration script is needed.
  • Seerr mapping/permission error: reachable base URL/key, exactly one imported native user, current Seerr permissions/quotas. Do not substitute an administrator identity.
  • Saved password field is empty: expected; blank keeps it. Settings changed: reload and review before resaving. Unsigned old settings: explicitly review/save elevated settings and reopen; never edit the key/signature.
  • OAuth mismatch: same app ID/secret, exact HTTPS callback/base path, same browser/device/cookie and correct trusted-proxy scheme. Request a fresh own link; never disable state/cookie checks.
  • Activity missing: owner/team test access, platform enabled, installed in the allowed server, human Use Activities permission. Blank/verifying: correct directory mapping, built bundle, enabled/saved in both places, trusted HTTPS/proxy reachability; test inside Discord.
  • DM/file denied: actual operator and bot channel permissions, Attach Files, allowed-server membership, recipient privacy; no Administrator workaround. Uncertain send: check its receipt, do not blindly retry.

Finish: own link works, an ordinary viewer sees only allowed media and no integration/unassigned messenger access, one safe read succeeds, and automatic deletion is still off. For Activity also verify real launch/OAuth/link/browse. Back up plugin state and its matching key consistently. Setup success does not mean production readiness.

Finish tutorial remembers only your walkthrough progress in this browser. It does not verify a connection, save settings or enable a feature. Pause/resume/restart remains available here whenever you need it.
